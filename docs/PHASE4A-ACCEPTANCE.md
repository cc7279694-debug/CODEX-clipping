# Phase 4A：ClipPlan 与 OpenFilm 工程验收标准

本文件列出要检查的事项；**不是测试结果**。每次运行的 PASS / FAIL / NOT_RUN / BLOCKED 与用户确认记录见 [Phase 4A 报告](evidence/PHASE4A-REPORT.md)。旧阶段报告和失败证据保持不变。

## 自动验证门禁

| 检查 | PASS 应有的证据 | 未满足时 |
| --- | --- | --- |
| 计划结构和时间 | schema 版本、唯一来源/轨道/片段 ID、已知有限数字、源范围合法；`timeline_duration` 与源时长及速度一致 | 拒绝无效计划，不能推测修复。 |
| 轨道与审核 | 同轨无重叠；不存在未知轨道或来源；待审/拒绝状态不能被当成已接受；改变已审核计划的内容后旧审核失效 | 对不允许的片段阻断工程生成；证据引用、人工标注不是说话安全保证。 |
| 素材和路径 | 明确指定的隔离测试素材存在；真实 SHA-256 和已知时长与计划一致；拒绝目录穿越和越权路径；写入前后源哈希一致 | 对应步骤 FAIL 或 BLOCKED，不改源文件。 |
| 映射与精度 | 同片段源起止、成片起止映射精确可复核；向 OpenFilm 支持的精度转换后无边界越界、零长、重叠或意外偏移 | 拒绝不能安全映射的计划，不能为了通过而舍入掉风险。 |
| 工程安全 | 显式指定已存在的 `allowed_output_root`，工程目标是该根下直接新子目录，且源/输出根不能互相嵌套；独占创建，重复执行不覆盖、源资产只读，隔离资产与来源可核对；模拟中断不删除已有文件 | 输出冲突或不安全路径受控失败，保留证据。 |
| 工程结构 | 打开并解析实际生成的 `film.html`，检查存在的媒体、相对引用、镜头排列、轨道及音画语义；执行与工具版本匹配的非破坏性检查 | 静态检查只能证明文件结构，不等于 Studio 加载或播放通过。 |
| 声音保障 | 显式验证视频自带音频、独立人声、B-roll 和背景音乐的轨道关系；未支持的组合不得自动发布为“已保护” | 无法证明就拒绝组合或标记 NOT_RUN / BLOCKED；不能从结构推断听感。 |
| 回归 | 运行必要的 Phase 3 测试和本阶段定向测试，报告各自数量、失败与跳过 | 不将模拟测试、脚本返回码或测试替身当作真实模型、OpenFilm 或用户验收。 |

建议同时覆盖无媒体、路径含 `..`、重复 ID、NaN/负数、源范围溢出、错误速度、片段重叠、哈希变化和重复输出；结果以实际测试覆盖和运行日志为准，不以清单本身宣称测试通过。

## 本阶段合成工程目标

在独立目录使用经实际检查的两段不同画面的短视频与一条独立音轨，合计约 15 秒、1080×1920、9:16；使用官方支持的 `film.html` / 片段引用格式，记录源时间及时间线时间，保留可追溯复制素材和 SHA-256。素材不存在时只在测试目录生成，不使用任何私人正式素材。

## 用户人工检查

只有在工程已生成且必要安全和静态检查通过后，提供准确的本机测试工程目录。用户在 OpenFilm Studio 中手动打开新工程，检查：

1. 能否加载工程，看到两段按顺序排列的画面及独立音频轨；画幅、时长和素材路径是否正确。
2. 逐段播放画面和声音，检查是否缺素材、人声/音频意外中断，是否有明显错位；这不能由脚本解析自动代替。
3. 实际尝试选中并调整一个测试片段，保存、关闭、重新打开，并确认修改保留；用户反馈前，编辑性为 WAITING_USER_CHECK。

不自动控制用户的图形界面，不自动导出，不修改 Phase 2 既有工程。需要用户试听、观看或操作才能确认的项目不能写 PASS。

## 状态词

- `READY_FOR_USER_CHECK`：合成工程确已生成并通过自动安全及结构门禁，等待用户手动验收；不是 ACCEPTED。
- `READY_FOR_REVIEW`：指定自动测试有结果并已记录，等待独立审查；并不证明 Studio 能打开。
- `PARTIAL`：部分能力完成，仍有缺项或未验证能力。
- `BLOCKED`：关键协议、兼容性、安全或环境门禁无法满足，停止依赖步骤。
- `PASS / FAIL / NOT_RUN / WAITING_USER_CHECK` 对单项测试分别记事实；任何人工项目没有用户实际确认就不标 PASS。
